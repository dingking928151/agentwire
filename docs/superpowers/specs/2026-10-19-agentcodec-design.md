# AgentCodec 基础版设计

## 意图与动机

做一个离线 Python SDK/CLI，用可复现基准验证：结构化的多 Agent 任务消息，以及每位用户手动维护的私有词典，是否能降低重复协作的实际 token 负担，同时无损保留任务语义与安全约束。

## 目标

- 提供 `encode`、`decode`、`validate`、`benchmark` 命令。
- 采用固定、版本化的通用消息结构，覆盖任务委派、状态、阻塞、下一步、证据、约束和审批要求。
- 支持人工编辑、按用户命名空间隔离、带版本的简易词典；只对完全匹配的词条替换短 ID。
- 对无效输入、未知协议/词典版本、未知短码和歧义采取拒绝解码，不猜测；基准中将其计为回退，并计入回退原文的 token 成本。
- 准备约 30 条合成任务，比较精简自然语言、JSON、DRIXL、通用 AgentCodec、AgentCodec+用户词典。DRIXL 对照固定为 [SamoTech/DRIXL v0.3.0](https://github.com/SamoTech/DRIXL) README 公布的 compact 消息格式，作为格式基线，不声称验证其 Python 包的运行行为。
- 报告每条消息成本、协议/词典初始化成本，以及复用 1、10、50 次时的摊销 token；报告字段往返一致率、关键约束丢失数和回退数。
- 仅统计本地 tokenizer 的 token 估算，不调用线上模型；明确这不是 API 实际计费或任务成功率测量。
- 按 Superpowers TDD 工作流开发，先写并运行失败测试，再写最少实现。

## 非目标

- 不连接 Cue、A2A、MCP、LangGraph、CrewAI 或任何真实 Agent。
- 不调用云端模型/API，不执行消息内含的动作，不发布 GitHub，不部署服务。
- 不自动学习/修改用户词典，不收集真实用户数据。
- 不压缩模型内部思维过程；只对外部 Agent 消息做可逆编码。
- 不宣称短格式在所有模型/tokenizer 上必然省 token，也不宣称该基准证明模型任务正确率相同。

## 设计决定

- 项目目录：`/workspace/agentcodec`。
- 技术栈：Python 3.11+、Pydantic v2、Typer、pytest、Hypothesis；token 统计使用 `tiktoken` 的 `o200k_base` 与 `cl100k_base`。DRIXL v0.3.0 对照由本项目根据公开 README 语法独立渲染，不安装或导入第三方 `drixl` 包。
- 通用内部表示是带版本的 Pydantic 模型；线上候选格式采用确定字段顺序和显式版本前缀，短码只用于固定枚举与用户词典中的精确词条，自由文本经过可逆转义后传递。
- 用户词典由用户手工提供 JSON 文件，含 `user_id` 与 `dictionary_version`；解码必须显式选择相同 user namespace，不能跨 namespace 查询。MVP 不做加密、认证或多用户服务端存储。
- `approval_required` 是数据字段，不是授权；工具执行权限不在该项目内。
- 否定、限制、预算/金额、日期和审批要求都属于关键字段；不得因为未匹配词典而丢弃。编码与解码必须保留完整规范消息。
- 解码错误返回明确的 `fallback_required` 状态，不让 LLM 猜；原文由发送端或调用方保留，回退时在基准中把原文重发 token 纳入总成本。
- 所有结论须标注 tokenization 方法、消息数和摊销假设；tokenizer 的数字不等于 API 的完整消息账单。

## 验收标准

- 合法 v1 消息可确定性编码/解码，规范化后的所有字段逐项相等。
- 未知版本、未知短码、用户命名空间不匹配、畸形转义、缺少必需字段均拒绝解码并指明回退，不静默忽略。
- Hypothesis 属性测试及普通单元测试通过。
- 基准能从版本化 JSONL 数据重跑，输出各 tokenizer/格式/复用次数的 token 计数和关键字段质量指标。
- CLI 在无 API 密钥、无网络连接时可运行（依赖已安装时）；无 DRIXL 可选依赖时清楚标示该对照无法运行。
- 文档清楚列出依赖、运行命令、限制、安全边界与实验解读方式。

## 实现阶段

基础版完成后先交付源码与本地测试结果；暂不推送、发布或连接外部 Agent。
